FrictionRL Live Demo

For every UPI payment in a session, the agent decides: approve it, ask for an OTP, or block it. This page runs our trained DQN network live in your browser on brand-new simulated sessions, next to the hand-written rule base. Nothing here is pre-recorded.

Live session

Each agent sees only what is on the payment (amount, device, payee, time) and what it has done so far. It is never told whether a fraudster has taken over.

Both agents start from the same user and the same takeover moment. After their first different decision the sessions can split: a blocked fraudster may retry with a smaller amount, an annoyed user may leave. For DQN, the bars show how many rupees the network expects to give up by choosing each action instead of its best one.

What would the agent do?

Build any payment situation and see the trained network's decision update instantly.

The rule base only uses the amount, device, payee, burst and OTP history. The DQN uses all 11 inputs, including how far into the session it is and how many OTPs it has already asked for.

DQN vs. the rule base

One session can go either way. Averaged over thousands, DQN earns about ₹470 more per session, halves fraud loss and keeps more users, with fewer OTPs.

Sessions are simulated with a JavaScript copy of frictionrl/env.py (synthetic source). The DQN is results/models/dqn_seed0_ltv3000, with its weights exported to the page; its Q-values match PyTorch to within 0.00002. Results from results/results_table.md. Keyboard: N next payment, S new session.
