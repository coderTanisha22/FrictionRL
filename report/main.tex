\section{Problem and Motivation}
Every UPI payment gets one of three decisions: \emph{approve} it, ask for an \emph{OTP}, or \emph{block} it.
Banks usually decide with fixed rules such as ``ask for an OTP above Rs\,X''. This creates a hard trade-off.
If the rules are too relaxed, a fraudster who has taken over an account can empty it. If they are too strict,
genuine users get OTP after OTP, feel annoyed, and eventually leave the app.

We treat this as a \textbf{sequential decision problem}, not a one-off classification, for four reasons:
\begin{itemize}
\item \textbf{Friction adds up:} every extra OTP makes the next one more likely to drive the user away.
\item \textbf{Early action pays later:} stopping a fraudster now prevents all of their later payments.
\item \textbf{Actions give information:} a failed OTP is strong evidence that the account was taken over.
\item \textbf{Fraudsters adapt:} a blocked fraudster often tries again with a smaller amount.
\end{itemize}
So we model one user session as a Markov Decision Process (MDP) and train RL agents to maximise the total
money saved in rupees, balancing fraud loss against user friction and churn.

\section{RL Formulation}
An \textbf{episode} is one user session of up to $H{=}20$ payments. With probability $0.15$ a fraudster takes
over the account at a random step $t_0\in[2,14]$. The agent is \emph{never told} when this happens; it has to
infer it from what it sees. We use a discount factor $\gamma{=}0.99$.

\subsection{State Space ($\mathcal{S}$)}
The agent observes an \textbf{11-dimensional continuous vector}, $s\in\mathbb{R}^{11}$, in three groups:
\begin{itemize}
\item \textbf{Current payment (5):} amount compared to the user's usual amount (log ratio), new device,
new payee, odd hour, and burst (sent right after the previous payment).
\item \textbf{Session context (2):} share of risky payments so far, and progress $t/H$.
\item \textbf{Agent's own history (4):} number of OTPs asked, an OTP failed, an OTP passed, number of blocks.
\end{itemize}
Whether a fraudster is present is hidden, so strictly this is a POMDP. The history features summarise what the
agent has learned so far (for example, a failed OTP), which makes the state close to Markov.
For tabular methods we group the state into $|\mathcal{S}_d|{=}432$ discrete states
($3$ amount levels $\times$ $3$ risk-flag levels $\times$ $3$ OTP counts $\times$ $2^4$ yes/no flags).

\subsection{Action Space ($\mathcal{A}$)}
The action space is \textbf{discrete} with three actions:
$\mathcal{A}=\{\textsc{Approve},\ \textsc{OTP},\ \textsc{Block}\}$, so $|\mathcal{A}|{=}3$.

\subsection{Reward Function ($\mathcal{R}$)}
The reward is the money gained or lost on each payment, in rupees (divided by $1000$ during training to keep
the numbers small for the neural networks). For a payment of amount $x$:
\begin{equation*}\small
\begin{aligned}
R ={}& 0.02x\,\mathbf{1}_{\text{genuine paid}} - (x{+}200)\,\mathbf{1}_{\text{fraud paid}}
 - 2\,\mathbf{1}_{\text{OTP}} - 50\,\mathbf{1}_{\text{genuine blocked}}\\
&- 3000\,\mathbf{1}_{\text{user leaves}} - 1500\,\mathbf{1}_{\text{genuine account frozen}}.
\end{aligned}
\end{equation*}
\textbf{Incentive design.} The bank earns a 2\% fee on genuine payments. A fraud payment costs the full amount
plus a Rs\,200 chargeback fee. Each OTP costs Rs\,2, and wrongly blocking a genuine user costs Rs\,50.
If a genuine user leaves, the bank loses their lifetime value of Rs\,3000. On purpose, there is
\textbf{no bonus for catching fraud}: only money counts, so the agent cannot score points by simply blocking
everything. A user leaving, or the account being frozen after a second block, ends the episode.

\section{Environment and Algorithms}
\subsection{Simulation Dynamics}
We built our own Gymnasium environment. Payments come from a synthetic generator in which genuine and fraud
payments \emph{overlap} (fraud tends to be about $2.5\times$ larger and more often from a new device or to a
new payee), so one payment alone is not enough to decide. Real payment features from the Kaggle IEEE-CIS
fraud dataset can also be replayed instead. How people react is simulated, because no dataset records it:
\begin{itemize}
\item A genuine user passes an OTP 97\% of the time.
\item A genuine user leaves after an OTP with probability $0.01+0.04\times$(OTPs so far), and after a wrong
block with $0.2+0.2\times$(blocks so far).
\item A fraudster beats the OTP 15\% of the time (SIM swap); after failing, they give up 70\% of the time.
\item After a block, the fraudster retries with half the amount 50\% of the time. A second block freezes the
account.
\end{itemize}

\subsection{Baselines}
We compare against non-learning policies: always approve, always ask for an OTP, random, an amount threshold
(OTP above a set amount, tested at 13 thresholds), and a hand-written rule base (e.g.\ ``if an OTP failed,
block'', ``if the amount is high and the device is new, ask for an OTP'').

\subsection{Choice of RL Algorithms}
We moved from simple to advanced methods, each matching a course lecture:
\begin{itemize}
\item \textbf{Model-based learning + Value/Policy Iteration:} count transitions to estimate $\hat T$ and
$\hat R$, then solve the learned MDP with value iteration and policy iteration.
\item \textbf{Tabular Q-learning:}
$Q(s,a)\leftarrow(1{-}\alpha)Q(s,a)+\alpha\,[\,r+\gamma\max_{a'}Q(s',a')\,]$, with decaying $\epsilon$-greedy
or an exploration function $f(u,n){=}u{+}k/(n{+}1)$.
\item \textbf{Approximate Q-learning:} a linear model $Q(s,a)=\mathbf{w}_a^\top\phi(s)$, whose weights we can read.
\item \textbf{DQN:} a neural network Q-function with a replay buffer (100k) and a target network
(synced every 1k steps).
\item \textbf{PPO:} an actor--critic method with a clipped objective ($\epsilon{=}0.2$) and GAE ($\lambda{=}0.95$).
\end{itemize}
The tabular, planning and linear methods are written from scratch in NumPy. DQN and PPO use Stable-Baselines3
and train for 500k steps each, keeping the weights that score best on separate validation sessions.

\section{Results}
Every agent is tested on 5{,}000 unseen sessions. Learned agents are trained with 3 random seeds.

\textbf{RL beats the rules.} DQN and PPO earn about Rs\,300 per session, while the best rule base loses
Rs\,155. That is roughly Rs\,470 more per session. They also halve fraud loss (Rs\,475 to 238) and cut churn
from 5.6\% to about 1\%, while asking for fewer OTPs (Table~\ref{tab:res}, Fig.~\ref{fig:pareto}).
Rules cannot do this because they ignore the session history and their own past actions.

\textbf{Planning vs.\ learning.} Value iteration took 226 sweeps and policy iteration took 5 steps, and both
gave exactly the same policy. Model-free Q-learning (Rs\,200) did slightly better than value iteration
(Rs\,178), because the learned model is built on grouped states that hide the fraudster. As a check, on a
fully Markov copy of the learned model, Q-learning matched the optimal policy on 99.1\% of decisions.

\textbf{What the agent learned.} DQN stays quiet in normal sessions and reacts quickly once the account is
taken over (Fig.~\ref{fig:beh}). The linear Q weights tell the same story: more OTPs make another OTP less
attractive (OTP fatigue), and a second block is strongly avoided because it freezes the account.

\textbf{Changing the customer value.} When we retrain PPO with a lifetime value of Rs\,1000, 3000 and 8000,
it asks for fewer OTPs (0.98, 0.49, 0.33 per session) and churn drops (2.2, 0.8, 0.3\%). In other words, the
more a customer is worth, the more carefully the agent avoids bothering them.

\textbf{Limitations and future work.} User and fraudster reactions are simulated, since no public data records
them. Next, we would like to train the fraudster as a second learning agent and use a recurrent policy to
handle the hidden state better.
